# Help chat: talk to the agent about a Need help case and redesign its test

Date: 2026-10-24
Plan: docs/plan/feat-help-chat.md

## What changed
- `agents/plan_revision.py` (new, pure):
  - validates a whole-plan redesign: carried steps form a strictly increasing prefix of earlier steps whose final attempt passed, each carried at most once, and at least one step runs;
  - `apply_plan_revision` writes the new plan, synthetic passing `step` attempts with `carried_from`, sets `next_step = C+1` and bumps `plan_version`, and moves the earlier plan into a `PlanRevisionRecord`;
  - also builds the side-by-side draft view and the plan fingerprint.
- `agents/types.py`, `agents/checkpoint.py`: optional `carried_from` (on attempts), and `plan_version` and `plan_revisions` (newest 5, malformed records dropped). The version is unchanged. `agents/timeout_bounds.py` is the pure home of `TimeoutBounds`. `ToolParameter.items_schema` describes object array items.
- `agents/services/orchestrator*.py`:
  - `_Progress` carries the new keys;
  - `_rebuild_state` writes carried lines, the redesign line and the help line labelled "Earlier plan, step N", and gives step C+1 the earlier failed digest as its retry note;
  - the verdict and attempt lines say which steps were carried and not re-run.
- `projects`:
  - `CasePlanRevision` and `CaseHelpRequest.agent_proposal_*`;
  - `case_plan_revision_services.py` (propose, discard, apply on Continue with id, fingerprint and re-validation checks) and `case_help_proposal_services.py`;
  - `continue_after_help(plan_revision_id, use_plan_revision)`. It is refused while a person's chat turn is live or when the pending draft is not the one shown.
  - Mark failed, Skip and abort supersede drafts.
  - `lock_help_request_for_chat` hands a not-yet-started auto-fix to the person.
  - A Night switch never auto-fixes a request that has a thread.
  - The Steps card shows carried rows and Earlier plans, and TestRail says what was carried.
- `machine_setup`:
  - thread kind `case_help` and the role module `thread_role.py`;
  - `open_help_chat`, `case_help_context` / `case_help_brief` (renamed from `auto_fix_brief`), `help_chat_tools` and `help_thread_state`;
  - a CASE_HELP prompt with HELP CHAT RULES;
  - the `machine_setup.help` socket event;
  - the thread page help panel: request header, side-by-side draft, the agent's suggestion, and Continue / Mark failed / Skip / Discard.
- UI: "Open help chat" / "Go to help chat" on the case card, and a "Help chat" link in the run banner.

## Why
A single note on Continue was not enough: the person often needs to ask the agent things, have it work on the machine, or fix a misunderstood test without losing the steps that already passed.

## Behaviour and contract changes
- URLs:
  - `machine_setup:help_chat_open` (POST `help/<pivot_id>/`);
  - `projects:test_run_case_plan_revision_discard`.
  - The Continue / Fail / Skip forms gain `plan_revision_id`, `use_plan_revision` and `return_thread_id`.
- Migrations:
  - `projects.0030_help_chat` (additive);
  - `machine_setup.0004_case_help_thread`, which adds a one-thread-per-help-request constraint. Before migrating, run the duplicate check in the plan's Verification step 1.
- New WebSocket event `help` on the setup socket. The `steps` payload gains `carried_from` / `carried_label`.
- No new settings, Celery task or controller protocol change. Deploy: run `migrate`, then restart Daphne/web and the execution workers.

## Notes for future changes
- The agent's `propose_resolution` note is shown only. It is never pre-filled into the person's note, because it would reach the tester as "Person: …".
- "Use the redesigned plan" is ticked by default on the thread page (side by side), unticked on the case page (summary only), and unticked again when a new draft arrives over the socket.
- Any module that `projects.services` imports cannot import `case_plan_revision_services` (cycle via `run_reopen_services`). Abort therefore updates drafts with plain querysets.
- Accepted residuals:
  - `projects` does not broadcast `help` on resolve or discard (the pages redirect back);
  - after a redesign, Q10 auto-fix eligibility may match an old step number and send a case to a person.
- Verified with:
  - pre-commit (strict mypy), `manage.py check` and `makemigrations --check`;
  - three throwaway-DB smoke scripts;
  - three reviewer and verifier passes.
  
  Not yet exercised against a live runner, the real model or a browser (plan Verification, manual steps 3–12).
