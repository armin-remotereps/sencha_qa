# OAuth 2.1 sign-in for the MCP gateway

Date: 2026-11-07
Plan: docs/plan/feat-mcp-oauth.md

## What changed
- `mcp_gateway/oauth_app.py`, `oauth_provider.py`: OAuth authorization server built from the MCP SDK 2.3 handler classes (our own metadata, so `none` is advertised for public DCR clients), backed by `services/oauth_*` (register, clients, start authorization, exchange code, refresh, revoke, consent, connections, access rule, sweep).
- `mcp_gateway/models.py` + migration `0002_oauth`: `McpOAuthClient`, `McpAuthorizationRequest`, `McpAuthorizationCode`, `McpGrant`, `McpOAuthToken` (only sha256 hashes of tokens, codes and consent handles; client secrets Fernet-encrypted).
- `services/authenticate_bearer.py` (replaces `authenticate_project_key.py`): accepts a `pha_` OAuth access token (one query) or the Connection key (unchanged path).
- `auto_tester/mcp_asgi.py`: path dispatcher; bearer pre-check and 10 MiB cap only on `/mcp` and `/mcp/`; per-IP throttles on the OAuth endpoints; the 401 carries `resource_metadata` and `scope` when OAuth is on.
- Django pages: consent `/connected-apps/authorize/<handle>/` and personal "Connected apps" `/connected-apps/` with revoke (`mcp_gateway/views.py`, `forms.py`, `templates/mcp_gateway/`); nav link; Connection key card note.
- `call_guard.guarded_call`: logs `auth=key|oauth grant=<id>`; neutral "not valid any more" text.
- nginx: one anchored regex location sends the OAuth paths to the `mcp` service.
- Beat `mcp_gateway.tasks.sweep_mcp_oauth` (hourly, `notify`).

## Why
ChatGPT connectors and claude.ai custom connectors only connect through MCP OAuth (discovery, dynamic registration, browser consent, short-lived tokens); the gateway only accepted the Connection key as a fixed bearer header.

## Behaviour and contract changes
- Settings: `MCP_OAUTH_ENABLED` (default False; needs an https `SITE_URL` origin) and `MCP_OAUTH_REDIRECT_HOSTS` (default `chatgpt.com,claude.ai,claude.com`; add `localhost,127.0.0.1` for loopback clients). Known connector hosts only accept their callback paths.
- New endpoints when enabled: `/.well-known/oauth-authorization-server`, `/.well-known/oauth-protected-resource[/mcp]`, `/authorize`, `/token`, `/register`, `/revoke` (issuer = `SITE_URL`, resource = `SITE_URL/mcp`, scope `mcp`, PKCE S256 only).
- Only an active member with a writable role can approve; superuser implicit access does not count. A grant ends on revoke, loss of write access, project archive or Connection key regeneration (checked on every call and refresh).
- Access tokens 1 h; refresh tokens rotate, expire after 30 days unused; replaying a rotated refresh token (after a 30 s grace) or a used code revokes the grant.
- MCP actions through OAuth are still recorded as "a tester".
- Migration `mcp_gateway.0002_oauth` (additive). Deploy must reload nginx.

## Notes for future changes
- Services never import the `mcp` SDK; the seam is `mcp_gateway/oauth_types.py`. SDK imports stay in `mcp_app.py`, `oauth_app.py`, `oauth_provider.py`, `services/authenticate_bearer.py`, `auto_tester/mcp_asgi.py`.
- The SDK's `TokenHandler` ignores `resource`; `oauth_app._token_endpoint` adds the check.
- Not tested against real ChatGPT or Claude clients yet: stage with `MCP_OAUTH_ENABLED=True` and walk the plan's Verification list before enabling in production.
- Deferred: move `hit_runner_throttle` to a neutral leaf module and the OAuth throttle policy out of `mcp_asgi.py`. CIMD is a possible follow-up.
