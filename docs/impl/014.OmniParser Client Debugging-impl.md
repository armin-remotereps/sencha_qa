# 014. OmniParser Client Debugging — Implementation

Plan: `docs/impl/014.OmniParser Client Debugging-plan.md`
Branch: `fix/omniparser-client-debugging`

## Root causes

Trace checked end to end (agent tool → `controller_find_elements` → channel layer →
`ControllerConsumer` → WebSocket → `ControllerClient._handle_find_element` →
`execute_find_element` → reply tracker). Message names and payloads aligned; the
failures were at the boundaries.

| Hypothesis | Verdict | Evidence |
|---|---|---|
| H1 Docker image lacks `controller_client` | **Confirmed** | Image built with the old `.dockerignore`: `ModuleNotFoundError: No module named 'controller_client'`, no `controller_client/` dir to ZIP. Fixed image passes `scripts/verify_server_image.sh`. |
| H2 stale controller connects, `find_element` silently times out | **Confirmed** | Client raised `ProtocolError` on the unknown type and `continue`d without replying; server ignored `client_version`. |
| H3 connected ≠ ready, cold load charged to the 120 s request | **Confirmed** | Lazy model construction inside the first `find_element`; hard-coded timeout; no readiness signal. |
| H4 environment (imports/weights/screenshot/device) | Environment-dependent | Covered by `python -m controller_client.diagnose` and phased errors. |
| H5 result payload too large | **Confirmed (deployed versions)** | Daphne 4.2.3 defaults incoming WebSocket messages to 1 MiB and closes with 1009; compose never raised it. Annotated PNG + elements is routinely several MiB. |
| Extra | Confirmed | Non-`ExecutionError` handler exceptions dropped the WebSocket; the handshake rejection message was discarded client-side. |

## Changes

### Packaging
- `.dockerignore`: keep tracked `controller_client/` source, exclude only `.venv/`, `omniparser/weights/`, `.env`, caches.
- `scripts/verify_server_image.sh`: builds the image and asserts the protocol import, presence of all ZIP sources and setup scripts, absence of venv/weights.
- Tests: `projects/tests/test_controller_client_zip.py` (full archive contents + `.dockerignore` guard).

### Transport
- `docker-compose.yml` api entrypoint: `--websocket-max-message-size 33554432 --websocket-max-frame-size 33554432`; documented in `CLAUDE.md` (plain `runserver` keeps the 1 MiB cap).
- Controller logs byte counts (screenshot, annotated PNG, base64, elements JSON, full message) and OCR/SOM/total seconds per `find_element`.
- `bound_find_element_result` downscales the annotated PNG (×0.75 steps, long edge ≥ 1280 px) until the message fits `OMNIPARSER_MAX_RESULT_BYTES` (default 8 MiB, `controller_client/example.env`); element coordinates stay in original pixels. Still too large → `OmniParserError(phase="serialize")` naming the env var.
- Test: `projects/tests/test_deployment_config.py` guards the Daphne flags.

### Compatibility
- `controller_client/protocol.py`: `CLIENT_VERSION = "0.2.0"`, `ClientCapability`, `CLIENT_CAPABILITIES`, `REQUIRED_CLIENT_CAPABILITIES`, `parse_handshake_capabilities`, `HandshakeAckPayload.message`, `ErrorCode.INCOMPATIBLE_CLIENT`.
- Server: `check_controller_compatibility()` runs before `mark_agent_connected`; `AuthenticationResult.status` is a `HandshakeStatus` literal (`ok|error|incompatible|already_connected`); rejected handshakes are logged with the client version. `Project.agent_client_version` / `agent_capabilities` stored and shown in the UI.
- Client: sends version + capabilities; a rejected ack raises `AuthenticationError("Handshake rejected (<status>): <server message>")`.

### Readiness
- Client: after the ack, `_initialize_omniparser` preloads the model in a background task and sends `omniparser_status` (`loading` → `ready`/`failed`, with phase/device/weights_dir/load_seconds). Warm reconnect sends only the current readiness. `load_omniparser_model()` is public, idempotent and lock-guarded (constructs once under concurrency; retries after failure). Load phases: `weights` → `imports` → `device` → `model_load`; find phases: `screenshot` → `ocr` → `som` → `serialize`.
- Server: `update_agent_omniparser_status()` persists `Project.agent_omniparser_status` and broadcasts it; `_wait_for_omniparser_ready()` gates `execute_test_run_test_case` (ready → continue, failed → `ControllerActionError` with the controller's message, timeout → `TimeoutError`).
- UI: `templates/projects/detail.html` badge (loading/ready · device/failed), failure panel, controller version, device and load time; `list.html` badge. Controller-supplied values are embedded with `json_script`, not `|safe`.
- Migration `projects/0011_add_agent_client_capabilities_omniparser_status.py` (additive).

### Diagnostics and errors
- `controller_client/omniparser_diagnostics.py` + `controller_client/diagnose.py`: `python -m controller_client.diagnose [--skip-inference]` runs imports → weights dir → weight files → screenshot → device → model load → one inference → serialized size, stopping at the first failure with an actionable hint. Setup scripts print the command.
- `OmniParserError(ExecutionError)` carries `phase/device/weights_dir/code`; the client sends it as `error` with `details`; `ReplyTracker.send_error` forwards `details`; `controller_find_elements` raises `ControllerActionError("<message> (<details>)")`.
- Client message loop: undecodable/unknown messages get an `UNKNOWN_COMMAND`/`INVALID_MESSAGE` reply (request id recovered via `peek_request_id`); handler exceptions get an `EXECUTION_FAILED` reply and the connection stays up.

### Timeouts
- `CONTROLLER_FIND_ELEMENT_TIMEOUT` (default 120) replaces the hard-coded value; `CONTROLLER_OMNIPARSER_READY_TIMEOUT` (default 600) bounds the readiness wait. Both in `settings.py` and `example.env`.
- `projects/tests/test_controller_timeout_ordering.py` asserts `find_element < SUB_AGENT_TIMEOUT_SECONDS < soft limit < hard limit`.
- Known tension (pre-existing): `drag` performs two lookups, so on a slow CPU it can exceed the 180 s sub-agent budget; raise `SUB_AGENT_TIMEOUT_SECONDS` if observed.

## Updating existing controller installations

Controllers older than protocol 0.2.0 are rejected at connect time. On each machine: download a fresh ZIP from the project page, unzip over the old folder, re-run the platform setup script, then

```bash
python -m controller_client.diagnose
python -m controller_client.main
```

Server: run `python manage.py migrate projects` and restart the `api` container so the Daphne flags apply.
