# 015. Punk Hazard Rebrand — Implementation

Spec: `docs/specs/015.Punk Hazard Rebrand.md` (Stage 2 of the rebrand plan). Approved
integration plan: `docs/impl/015.Punk Hazard Rebrand-plan.md`. Visual source of truth:
`ui-prototype/` (14 static pages + `assets/prototype.css`).

## Decisions taken with the user

| Question | Decision |
| --- | --- |
| Application context storage | `Project.application_url` + `Project.application_platform` (web / windows / both) added; `project_prompt` stays the single free-text notes field and "Refine with AI" keeps working. The agent receives URL + platform prepended to the prompt (`build_agent_project_context`). |
| Named runs / durations | `TestRun.name`, `TestRun.started_at/finished_at`, `TestRunTestCase.started_at/finished_at` added; `TestRun.display_name` falls back to "Run #id". |
| Settings tab / Account page | Dropped. Project tabs are Overview / Test Cases / Runs / Environment; edit / duplicate / archive / restore live in the Projects-list dialogs; user menu is Sign out only. |
| CSS approach | Tailwind CDN removed. `ui-prototype/assets/prototype.css` became `static/css/punk-hazard.css`; Alpine.js 3.14.9 (+ `@alpinejs/focus`) pinned. |

Internal names (`auto_tester` package, URL paths, model names) are unchanged.

## Schema

Migration `projects/0012_punk_hazard_context_and_run_fields` — additive only, with a
reversible `RunPython` backfill: finished/cancelled runs get `started_at=created_at`,
`finished_at=updated_at`; running runs get `started_at=created_at`; finished pivots get
both timestamps. Existing data therefore shows dates/durations and the dashboard's 7-day
windows are not empty after upgrade.

## Backend

- Application context: `save_application_context`, `build_agent_project_context` (hooked
  into `execute_test_run_test_case`).
- Machine/primary-action derivation shared by overview + dashboard: `MachineState`,
  `get_machine_state`, `PrimaryAction`, `resolve_primary_action`.
- `ProjectOverview` / `get_project_overview` (case counts, machine state, latest/active run,
  `recent_runs`, 30-day pass rate, primary action).
- Run readiness as a UI gate: `ReadinessCheck`, `RunReadiness`, `get_run_readiness`

  `start_test_run` keeps its `ValueError` semantics.
- Runs: `create_test_run_with_cases(name=...)`, `suggest_run_name`, `rerun_failed_cases`

  `list_failed_case_titles`, `get_case_position`, `_annotate_run_counts` shared by
  `list_test_runs_for_project` and the overview. Failures are listed first in
  `list_test_run_cases`.
- Timestamps set in `start_test_run`, `_mark_pivot_in_progress`, `_finalize_pivot`,
  `_mark_pivot_failed`, `_mark_pivot_cancelled`, `_update_test_run_status_if_needed`,
  `abort_test_run`; cleared by `reset_test_run`.
- Projects list: `list_projects_for_user(include_archived=...)` with `case_count`,
  `member_count`, `latest_run_id` annotations (membership via `id__in` subquery so the
  M2M join does not distort counts), `prefetch_related("tags")`,
  `get_latest_runs_by_project`.
- Test cases: `last_run_at` annotation (NULL when never run), `bulk_delete_test_cases`.
- Wizard read services so views stay ORM-free: `get_project_tag_names`, `count_test_cases`,
  `get_run_case_picker` (first 200 cases + total).

### `dashboard/services.py` (new)
`get_dashboard_data(user)` → `DashboardData(summary, attention, projects, activity)`.
Constant query count regardless of project count (project-id subquery, filtered
`Count`s, `Subquery`/`OuterRef` + `in_bulk`, `select_related`), guarded by a scaling test.
"Recent projects" is ordered by `updated_at` (there is no last-accessed tracking).

### Views / URLs / forms
- `projects:detail` now renders the overview. New: `environment`, `application_context`,
  `restore`, `test_case_import` (old uploads page, `upload_list` alias removed),
  `test_case_bulk_delete`, `test_run_rerun_failed`, wizard `create` (step 1) +
  `setup_details/context/cases/machine/run`.
- Wizard is not resumable and stores no state; every step reads real project state.
  Project creation redirects into step 2; "Restart setup wizard" opens step 1 in edit mode.
  A blocked "Start run" re-renders with the selection preserved and an error message.
- Formerly-silent invalid forms now surface `messages.error(form_error_text(form))`
  or re-render inline errors (project edit, test case create/edit, upload create ×3,
  copy-to-project, run create). `next` redirects are validated with
  `url_has_allowed_host_and_scheme` (login + upload).
- Forms: `ApplicationContextForm`, `TestRunCreateForm` (case ids bound to the project —
  doubles as IDOR protection), `form_error_text`; Tailwind class constants replaced by
  `input` / `textarea` / `select`.
- `auto_tester/context_processors.py::branding` supplies `brand_name` / `brand_tagline`.
- `auto_tester/urls.py` serves static files in DEBUG (`staticfiles_urlpatterns`) because
  Daphne, unlike runserver, does not.

## Lessons recorded

- Django `{# … #}` comments are single-line; multi-line ones leak into the HTML. Use
  `{% comment %}` for blocks (documented in CLAUDE.md).
- `{% include … only %}` drops `csrf_token` and `request`: any partial that renders a POST
  form or pagination must not be included with `only`. The render smoke test asserts one
  CSRF token per POST form on every page.
- In an Alpine method invoked from a child scope, `this.$el` is the child element; use
  `this.$root` to reach the component element.
- `case` is a JavaScript reserved word — don't use it as an Alpine variable.
- `timesince` renders `argument − value`: durations are `started_at|timesince:finished_at`.

## Tests

First DB-backed tests in the repo (`django.test.TestCase`, plain `objects.create`,
helpers in `projects/tests/helpers.py`; Postgres must be up). 219 tests:
readiness, timestamps, rerun-failed, project context / overview / list annotations,
case position, `last_run_at`, wizard views, project views (restore, archived filter,
formerly-silent forms), dashboard services (empty / populated / scoping / query scaling)
and views, login (`next` validation), and a render smoke test that GETs every page as
member / non-member / anonymous.

`mypy .` strict: clean. black/isort: clean on all touched code (pre-existing
`controller_client/` formatting differences are out of scope — that package has its own
tooling).

## Verified in the browser (Playwright)

Login → dashboard empty state → wizard end to end (real XML import through the Celery
`upload` queue) → overview → test cases (row menu, edit dialog, bulk bar, add-to-run) →
draft / finished / not-started run and case pages → runs → environment → projects list
(duplicate, archive, show archived, restore) → populated dashboard → import →
application context; 375 px mobile (topbar menu, stacked stats, stacked table records).
Zero console errors on every page.
