# Punk Hazard UI Integration (Rebrand Stage 2)

## Context

`ui-prototype/` (14 static pages + `assets/prototype.css`, 1,865 lines) is the approved visual source of truth for rebranding **Auto Tester → Punk Hazard** (see `PUNK_HAZARD_REBRAND_PLAN.md`, Stage 2). The Django app today renders ~13 Tailwind-CDN templates with inline Alpine.js and no brand assets. This task integrates the prototype into Django without breaking imports, controller connectivity, Celery execution, WebSockets, logs or screenshots.

Internal names (`auto_tester` package, URL paths, model names) stay unchanged — only user-facing surfaces change.

### Decisions locked with the user
1. **Application context**: add `Project.application_url` + `Project.application_platform` (web / windows / both). `project_prompt` stays as the single notes field; Refine-with-AI stays. Agent receives URL + platform prepended to the prompt.
2. **Runs**: add `TestRun.name`, `TestRun.started_at/finished_at`, `TestRunTestCase.started_at/finished_at`.
3. **No Settings page, no Account page.** Project tabs = Overview / Test Cases / Runs / Environment. Edit / duplicate / archive / restore live in Projects-list dialogs. User menu = Sign out only.
4. **Drop Tailwind.** `prototype.css` becomes the app stylesheet; Alpine.js stays (pinned) for modals, tabs, WebSockets, bulk selection.

### Terminology (apply everywhere user-facing)
Controller Client → **Test Runner** · Agent connected → **Test machine connected** · OmniParser → **Visual engine** (advanced diagnostics only) · Project Prompt → **Application context** · Test Runs → **Runs** · Uploads → **Import** / "Import from TestRail" · success → **Passed** · started → **Running** · waiting → **Draft** · Force Disconnect → **Disconnect test machine** · API key → **Connection key** (advanced only) · Title pattern `<Page> · <Project> · Punk Hazard`. Tagline: "AI testing on real applications."

## Phase 2 — Backend (services / views / URLs / forms)

## Phase 4 — Onboarding wizard (`templates/projects/wizard/step_*.html`, `layouts/app.html` + `.narrow`)

Shared `wizard_steps.html` (5 steps, `is-done` linked / `is-current` / upcoming) and `wizard_actions.html` (Back / Save and continue). No wizard state stored; each step reads real project state.

1. **Project details** — `GET/POST projects:create` (new project) and `projects:wizard_details` (restart, edit mode: name/tags pre-filled). Info alert "What a project represents". On success → step 2.
2. **Application context** — `ApplicationContextForm` (application_url, application_platform, project_prompt textarea with guidance placeholder covering environment / navigation / authentication notes; warning alert about test accounts). **Refine with AI (optional)** → port of `projectPrompt` component (`refine_prompt` 202 + `prompt_refined` over agent-status WS). Save → step 3.
3. **Add test cases** — radio cards Import from TestRail / Create manually. Import posts to existing `upload_create` with `next=` back to this step; progress list via upload WS; validating skeleton, failure alert, success alert. Continue enabled when project has ≥1 case or "Create manually" chosen.
4. **Connect a test machine** — explainer card, download card, `os_setup_tabs`, Connection status card live via agent-status WS (Waiting for connection… / connected + machine name), `advanced_diagnostics` collapsed. Continue always allowed (machine can be connected later; readiness check will flag it).
5. **First run** — `TestRunCreateForm` (name, default "First run — {Mon d}"), case checklist with select-all (paginated? no — first 200 cases, with link to Test Cases if more), **Ready to run?** checklist computed from `get_run_readiness(project, selected_count)` and refreshed live via agent-status WS for the machine/visual-engine checks. **Start run** → creates run + starts → redirect to run detail. If creation succeeds but start fails (race), redirect to run detail with error message (draft shown with checklist).

## Execution approach

Sequential phases, parallel agents inside each: Phase 0+2 via `django-view-architect` (services/views/forms/urls) — templates cannot be finished before the URL names and context keys exist; Phase 1 (`frontend-craftsman`: CSS/JS/base/partials/login) runs in parallel with Phase 2; Phase 3+4 templates split across 2–3 `frontend-craftsman` agents by page group (dashboard+projects+overview+environment / test cases+import+runs / run detail+case detail+wizard) once Phase 2 context contracts are fixed. Mypy + tests + uncle-bob after.
