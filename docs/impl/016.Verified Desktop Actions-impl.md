# 016. Verified Desktop Actions — Implementation

Bug report (no spec file): the OmniParser-based `click` tool sometimes clicked the wrong
element and still reported success. Approved plan:
`docs/impl/016.Verified Desktop Actions-plan.md`.

## Decisions taken with the user

| Question | Decision |
| --- | --- |
| Where to check | Both: a vision check of the matched candidate **before** acting, and a before/after screenshot check of the outcome **after** acting. |
| Expected result | `click`, `hover`, `drag` accept an optional `expected_result` argument that drives the post-action question. `click` always confirms (generic "the UI reacted" fallback); `hover`/`drag` confirm only when `expected_result` is given. |
| Scope | `click`, `hover`, `drag` (all OmniParser tools). `browser_click` unchanged. |
| Attempt cap | Hard-coded `MAX_VERIFY_ATTEMPTS = 10` in `agents/services/verified_element_actions.py`. No env var. |

## Flow per tool call

1. `parse_screen` runs OmniParser once and publishes the annotated image (`controller_omniparser`).
2. `match_element` asks the matcher for the best box, with already-rejected boxes removed
   from the text list and named as "Already ruled out, do not choose". If the matcher still
   picks one, `RejectedElementChosenError` is raised and treated as a failed attempt.
3. `verify_candidate` (annotated image + candidate line) answers YES/NO. NO → record the
   rejection, exclude that index within the current parse, retry from step 2.
4. Before screenshot → controller action → 1 s settle → after screenshot (published under
   the tool name) → `verify_action_outcome` with both images, the action summary and the
   expected result. NO → record the rejection by screen position (10 px tolerance, so a
   fresh parse with shifted indices still excludes it) and start again at step 1.
5. Success message: `... (verified on attempt K)` plus a `Skipped candidates:` list when
   K > 1. After 10 attempts `ActionVerificationError` is raised and `safe_tool_call` turns
   it into an error result listing every attempt.

`VerificationBudget` owns the counter, the rejection history (`RejectedCandidate` with the
attempt it happened on), the sub-agent deadline (stops with < 5 s left) and the
cancellation check (`AgentCancelledError` now passes through `safe_tool_call`). For `drag`
an outcome rejection blames both the start and end elements.

## Files

- New `agents/services/action_verifier.py` — vision-only YES/NO checks (`verify_candidate`,
  `verify_action_outcome`, `_parse_verdict`).
- New `agents/services/verified_element_actions.py` — `VerificationBudget`,
  `resolve_verified_element`, `confirm_action`, `take_before_screenshot`,
  `format_verified_message`, `default_click_expectation`.
- `agents/services/controller_element_finder.py` — split into `parse_screen` +
  `match_element(is_excluded=...)`; `find_element_coordinates` kept as a thin composition.
- `agents/services/tools_controller.py` — `click`/`hover`/`drag` share
  `_run_verified_action` (budget + retry loop inside `safe_tool_call`) and
  `_confirm_or_finish`; new kwargs `expected_result`, `cancellation_check`, `deadline`.
- `agents/services/tool_registry.py`, `tool_definitions.py`, `prompt_parts.py` — pass the
  new arguments, expose `expected_result` in the schema, teach the agent to use it and to
  re-describe the element after a verification error instead of repeating the call.
- `agents/services/tool_utils.py` — re-raise `AgentCancelledError`.
- `agents/types.py` — `Verdict`, `RejectedCandidate`. `agents/exceptions.py` —
  `RejectedElementChosenError`, `ActionVerificationError`.

## Tests

`python manage.py test agents` — 101 tests. New: `test_action_verifier.py`,
`test_verified_element_actions.py`, `MatchElementTests` in
`test_controller_element_finder.py`, rewritten `ClickToolTests` plus `HoverToolTests` /
`DragToolTests` in `test_tools_controller.py`. All controller and LLM calls are patched.

## Cost / follow-ups

- Every click now adds two vision calls, two screenshots and a 1 s settle; raise
  `SUB_AGENT_TIMEOUT_SECONDS` if runs become noticeably slower.
- If the generic click fallback rejects clicks that legitimately change nothing visible,
  push the agent harder (prompt) to pass `expected_result` rather than loosening the check.
