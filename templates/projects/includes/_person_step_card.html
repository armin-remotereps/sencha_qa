The case page defines the Alpine components personStepAsk (the Q&A list, replaced from the "person_step_questions" socket event via x-text only) and personStepDraft (keeps the half-typed note/output in sessionStorage per step id and round; cleared on submit) and personStepQuestionDraft (keeps the typed question per step id; after a submit it is put back only when the ask view redirected with ?ask=refused, else dropped). Report / Overrule / Mark failed / Mark blocked share one form and post to their own URL via formaction (the help card convention); the decision views read person_step_id and note and ignore the report fields.
